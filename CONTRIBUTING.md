# Contributing to JavaFlow

First off, thank you for considering contributing to JavaFlow! It's people like you that make JavaFlow such a great tool for the community.

## 🧠 How can I contribute?

There are many ways you can contribute to JavaFlow:
*   **Report Bugs:** If you find a bug, please open an Issue with steps to reproduce it.
*   **Suggest Enhancements:** Have an idea for a new feature? We'd love to hear it! Open an Issue to discuss it.
*   **Write Code:** Check out the open issues. We use labels like `good first issue` or `help wanted` to highlight tasks that are great for new contributors.
*   **Improve Documentation:** Fix typos, add examples, or clarify explanations in the README or the Info overlays in the app.

## 🛠️ Local Development Setup

To get the project running locally for development, follow these steps:

1. **Fork the repository** to your own GitHub account.
2. **Clone your fork** locally:
   ```bash
   git clone https://github.com/YOUR-USERNAME/Java-arch-visulization.git
   cd Java-arch-visulization
   ```

3. **Install dependencies for both Backend and Frontend**:
   ```bash
   cd backend && npm install
   cd ../frontend && npm install
   ```

4. **Start the development servers**:
   *   In one terminal, start the backend:
       ```bash
       cd backend && npm run dev
       ```
   *   In a second terminal, start the frontend:
       ```bash
       cd frontend && npm run dev
       ```

5. **Make your changes!** The frontend will hot-reload automatically, and the backend (if using `nodemon`) will restart on file saves.

## 🚀 Submitting a Pull Request

1. Create a new branch for your feature or bugfix: `git checkout -b feature/my-awesome-feature`.
2. Make your changes and commit them with clear, descriptive commit messages.
3. Push your branch to your fork: `git push origin feature/my-awesome-feature`.
4. Go to the original JavaFlow repository on GitHub and click **New Pull Request**.
5. Fill out the Pull Request template with details about your changes.

## 🧑‍💻 Architecture Overview for Contributors
If you're modifying the execution engine, keep in mind:
*   **`backend/TraceGenerator.java`**: This is where the magic happens. It attaches to a target JVM using the Java Debug Interface (JDI) to step through bytecode and extract state.
*   **`backend/server.js`**: The Express server that handles compilation and invokes the `TraceGenerator`.
*   **`frontend/`**: A standard React + Vite application. State is primarily driven by the massive JSON trace array generated by the backend.

We look forward to your contributions!
